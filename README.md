# 4-20-to-Modbus

Прошивка преобразователя 4–20 мА → Modbus RTU на STM32F103C8T6,
FreeRTOS и изолированном трансивере CA-IS2092VW.

Версия 1.1.1 исправляет порядок запуска IWDG: запуск выполняется до
настройки PR/RLR и ожидания завершения обновления регистров, как в
[HAL ST](https://github.com/STMicroelectronics/stm32f1xx-hal-driver/blob/master/Src/stm32f1xx_hal_iwdg.c).
В 1.1.0 на реальном STM32 обнаружен перезапуск до старта планировщика;
для автономного запуска используйте 1.1.1. Калибровка не менялась.

## Подключение по схеме PCB_Project

| Сигнал | STM32 | Назначение |
| --- | --- | --- |
| ADC_4_20MA | PA0 / ADC1_IN0 | Выход аналогового каскада |
| LOOP_FAULT | PA1 | 1 — токовая петля разомкнута / недостаточный ток |
| RS485_DE_RE | PA8 | Общий DE + /RE: 0 — приём, 1 — передача |
| USART1_TX | PA9 | Вход DI трансивера |
| USART1_RX | PA10 | Выход RO трансивера |
| LED_STATUS_B/G/R | PB3 / PB4 / PB5 | Внешняя индикация, активный высокий уровень |

Во время сброса GPIO ещё не управляет PA8; для однозначного состояния линии
при включении питания можно предусмотреть внешнюю подтяжку DE_RE к GND.
После инициализации PA8 установлен в 0. Перед DMA он поднимается в 1,
выдерживается не менее 2 мкс, а после **USART TC**, когда передан последний
стоповый бит, возвращается в 0. DMA TC лишь включает ожидание USART TC.
На старте выдерживается 50 мс для установления изолированного питания.
При передаче внутренний приёмник USART выключен. Зависшая передача имеет
тайм-аут с освобождением линии; DMA-ошибка также дожидается окончания USART.

Полярность и время включения драйвера проверены по
[даташиту CA-IS2092VW, версия 1.07](https://e.chipanalog.com/Public/Uploads/uploadfile/files/20250513/CAIS2092xdatasheetVersion1.07en20241217.pdf).

## Modbus и настройки

Версия прошивки: **1.1.1**. Начальные параметры: **адрес 1, 9600 бод, 8N1**.

**SW1 (PA15):** включённый переключатель замыкает PA15 на GND.
Его положение проверяется только при включении/сбросе, с подавлением дребезга.
Если SW1 замкнут, активны 1/9600/8N1; записанные настройки и калибровка
не стираются. Новые параметры можно подготовить и сохранить через Modbus,
но они вступят в силу после размыкания SW1 и перезапуска. Переключение SW1
во время работы само по себе параметры не меняет. В сервисном режиме
при исправном измерении дежурная индикация синяя; в обычном — зелёная. Поддержаны функции
`0x03`, `0x06`, `0x10`, exception-ответы и широковещательные записи (адрес 0,
без ответа). CRC-ошибки, аппаратные ошибки приёма и чужие адреса игнорируются.
Максимальный RTU ADU — 256 байт. Разбор выполняется задачей; прерывания
принимают байты, фиксируют завершение кадра и обслуживают DMA/TC.

| Адрес | Назначение | Доступ |
| --- | --- | --- |
| `0x0000` | Записать **1**: сохранить и применить настройки | RW |
| `0x0001` | Адрес устройства, 1…247 | RW |
| `0x0002` | Скорость: 0=1200, 1=2400, 2=4800, 3=9600, 4=19200, 5=38400, 6=57600, 7=115200 | RW |
| `0x0003` | Чётность: 0=нет, 1=even, 2=odd | RW |
| `0x0004` | Число стоповых битов: **1 или 2** | RW |
| `0x0010…0x0013` | Действующие адрес / код скорости / чётность / стоповые биты | RO |
| `0x0030` | Калибровочный ADC_raw для 4 мА ×10 = 2331 | RO |
| `0x0031` | Калибровочный ADC_raw для 20 мА ×10 = 39225 | RO |
| `0x0100` | Ток, мкА | RO |
| `0x0101` | Напряжение АЦП, мВ | RO |
| `0x0102` | Усреднённый отсчёт АЦП | RO |
| `0x0103` | Битовая маска статуса | RO |

Адреса в таблице — нулевые адреса непосредственно в RTU-запросе.
Записи `0x0001…0x0004` меняют подготовленные настройки. Запись 1 в `0x0000`
сохраняет их во Flash с CRC. Подтверждение передаётся со **старым адресом
и параметрами UART**, затем применяется новая конфигурация. Чтение настроек
показывает подготовленные значения. Чтение `0x0000` возвращает 0.

Можно записать все пять регистров одним `0x10`: `[1, адрес, скорость,
чётность, стоповые биты]`. Сначала проверяется весь набор; ошибка значения,
адреса или сохранения не изменяет подготовленные/активные настройки в RAM.

## Надёжность и хранение

Две последние страницы Flash (`0x0800F800`, `0x0800FC00`, по 1 КБ) исключены
из области прошивки; линкер ограничивает программу 62 КБ.
Запись содержит версию формата, номер поколения, настройки связи,
существующие калибровочные точки, CRC и финальную отметку завершения.
Новая запись пишется на другую страницу; предыдущая не стирается до
проверки и завершения новой. При сбое записи/питания используется последняя
полная корректная запись. Если корректной копии нет, применяются начальные
параметры и встроенная текущая калибровка. Повторное сохранение идентичных
данных не стирает Flash.

Старые 10-байтовые настройки по `0x0800FC00` читаются для совместимости.
Первый SAVE_CONFIG переносит их в новый формат, сохраняя старую страницу
до успешного завершения миграции. Настройки связи и калибровка — разные
поля записи: SW1 и смена адреса/скорости не изменяют калибровочные точки.
Команды изменения калибровки через Modbus не добавлялись.

Полное стирание Flash программатором удаляет обе копии; двухстраничное
хранение не защищает от намеренного mass erase. Встроенные точки 2331/39225
при этом остаются в загруженной программе и используются как исходные.

Аппаратный IWDG обслуживается из Idle Hook только при свежих подтверждениях
от задач измерений и Modbus (моложе 1 с). Modbus подтверждает работу каждые
100 мс даже без запросов и во время длительной передачи. ADC подтверждает
работу только при новых данных DMA. Если планировщик завис или Idle не
получает процессор, обновления IWDG также прекращаются.
Настройка /64, reload=4095 даёт приблизительно 4,37…8,74 с после последнего
обслуживания при LSI 30…60 кГц; это не точный таймер. При отсутствии
подтверждения задержка до перезапуска включает порог 1 с.

Критические ошибки, assert, нехватка heap и переполнение стека освобождают
PA8/DE, записывают код ошибки в backup-регистры и запрашивают системный
перезапуск. Backup-причина сохраняется через сброс при наличии питания;
при полном исчезновении основного/резервного питания она может потеряться.
Сырые причины сброса RCC также доступны через Modbus.

Ошибка DMA либо три периода без новых отсчётов запускают восстановление
ADC/DMA. При постоянной неисправности watchdog перезапустит устройство.
Возраст последнего корректного измерения проверяется при чтении независимо
от задачи ADC; спустя 300 мс выставляется STALE. Неисправность не должна
выдаваться как нормальное старое значение. События восстановления сохраняются
в счётчиках до сброса питания/контроллера.

## Измерение тока

TIM3 запускает ADC1 с частотой 1 кГц. Циклический DMA собирает 32 отсчёта;
усредняются завершённые половины по 16 отсчётов. Задача раз в 100 мс публикует
согласованный снимок; Modbus читает все измерительные регистры из одного
снимка. Программного запуска ADC и конкурирующего чтения DR нет.

Для этой платы применена двухточечная калибровка по калибратору токовой
петли от 17 октября 2026 года. На каждой точке снято десять показаний:

| Задано | Средний ADC_raw | До калибровки |
| --- | ---: | ---: |
| 4 мА | 233,1 | 3,9254 мА |
| 10 мА (контрольная точка) | 1614,9 | 9,8736 мА |
| 20 мА | 3922,5 | 19,8080 мА |

Ток рассчитывается непосредственно из отсчёта АЦП:

```text
I[мкА] = 4000 + (ADC_raw × 10 − 2331) × 16000 / 36894
       ≈ 4,3367485 × ADC_raw + 2989,1039
```

В прошивке используются целые числа и округление до ближайшего мкА.
После поправки независимая точка 10 мА расчётно даёт 9,9925 мА
(до округления отдельных показаний). После загрузки калиброванной прошивки проверена точка 10 мА: десять
ответов с правильным CRC, среднее 9,9958 мА, диапазон 9,993…9,997 мА,
отклонение от задания −4,2 мкА. Новая версия 1.1.0 сохраняет эти коэффициенты;
её собственные аппаратные приёмочные испытания ещё не выполнены.

Исходные отсчёты сохранены в `calibration/2026-10-17.json`. Константы
`SENSOR_CAL_RAW_4MA_X10` и `SENSOR_CAL_RAW_20MA_X10` находятся в
`App/Inc/SensorMath.h`; это средние отсчёты, умноженные на десять.
Калибровка относится к конкретной измеренной плате и условиям измерения.
Для другой платы нужны собственные точки. Регистр напряжения АЦП по-прежнему
использует номинальное опорное 3,3 В; он отдельно не калибровался.

Вне 4–20 мА формула экстраполируется, чтобы сохранить диагностику выхода
за диапазон; значение ограничивается диапазоном uint16_t. При обрыве или
насыщении аналогового каскада численное значение тока недостоверно — проверяйте status.

| Бит status | Значение |
| --- | --- |
| `0x0001` | LOOP_FAULT подтверждён тремя последовательными периодами ADC |
| `0x0002` | Ток ниже 3,8 мА; сброс выше 3,9 мА; также при подтверждённом LOOP_FAULT |
| `0x0004` | Ток выше 20,5 мА; сброс ниже 20,4 мА |
| `0x0008` | АЦП ≥4090, насыщение сверху |
| `0x0010` | Нет новых данных DMA / измерение старше 300 мс |
| `0x0020` | Обнаружена ошибка DMA; выполняется восстановление |

## Диагностика Modbus

32-битные значения занимают два регистра: **сначала старшие 16 бит**.
Читать пару нужно одним запросом. Весь блок диагностики формируется из
одного снимка, поэтому половины счётчиков согласованы.

| Адрес | Значение |
| --- | --- |
| `0x0200…0x0202` | Версия major/minor/patch: 1 / 1 / 1 |
| `0x0203` | Ревизия платы: 0 = не закодирована/не подтверждена |
| `0x0204` | Флаги: bit0 SW1/service; bit1 сохранённые настройки; bit2 калибровка действительна; bit3 измерение свежее; bit4 новый журнал; bit5 старый формат |
| `0x0205…0x0206` | Причины последнего сброса, флаги RCC_CSR (31…25), без изменения нумерации битов |
| `0x0207` | Последняя сохранённая причина аварии |
| `0x0208…0x0209` | Время работы, секунды, uint32 |
| `0x020A…0x020B` | Возраст корректного измерения, мс; `0xFFFFFFFF` = ещё нет данных |
| `0x020C` | Минимальный остаток heap с момента старта, байты |
| `0x020D` | Текущий остаток heap, байты |
| `0x020E…0x0210` | Минимальный свободный стек ADC / Modbus / LED, в 32-битных словах |
| `0x0211…0x0216` | 96-битный UID STM32: три слова, каждое high/low |
| `0x0217` | Свежие heartbeat: bit0 ADC, bit1 Modbus, bit2 LED |

Коды аварий `0x0207`: 0 нет, 1 Error_Handler/assert, 2 HardFault,
3 MemManage, 4 BusFault, 5 UsageFault, 6 NMI, 7 stack overflow,
8 malloc failed, 9 отсутствие новых ADC-данных, 10 зависание задачи Modbus.
Причина из backup — дополнение к аппаратным reset flags; она не заменяет их.

| Пара регистров | Счётчик uint32 |
| --- | --- |
| `0x0220…0x0221` | Принятые байты |
| `0x0222…0x0223` | Кадры, принятые без аппаратной ошибки/ошибки интервалов |
| `0x0224…0x0225` | Завершённые передачи |
| `0x0226…0x0227` | Ошибки CRC |
| `0x0228…0x0229` | Ошибки UART / межбайтового интервала |
| `0x022A…0x022B` | Переполнения RX-буфера |
| `0x022C…0x022D` | Переполнения очереди кадров |
| `0x022E…0x022F` | Ошибки ADC DMA |
| `0x0230…0x0231` | Перезапуски ADC/DMA |
| `0x0232…0x0233` | Ошибки TX DMA |
| `0x0234…0x0235` | Тайм-ауты передачи |
| `0x0236…0x0237` | Отправленные Modbus exception-ответы |
| `0x0238…0x0239` | Ошибки сохранения Flash |

Счётчики насыщаются на `0xFFFFFFFF` и обнуляются при запуске. Завершённая
передача означает USART TC, а не подтверждение получения master-устройством.

## Сборка и проверки

Требуются Arm GNU GCC **11 или новее**, PowerShell и ripgrep.
Линкерный скрипт использует `READONLY`, поэтому старые GCC не подходят.

```powershell
./tools/build.ps1 -Configuration Debug
./tools/build.ps1 -Configuration Release
# При другом расположении GCC:
./tools/build.ps1 -Toolchain 'C:/path/to/gcc/bin'
```

Результат: `build/verify-debug/4-20-to-Modbus.hex` (или `verify-release`).
Все исходники собираются заново. Для кода проекта включены `-Wall -Wextra
-Werror`; у vendor-драйверов подавлено предупреждение unused-parameter.

```powershell
python -m pip install --target build/test-deps -r tests/requirements.txt
python tests/run.py
```

Тесты исполняют настоящий ARM-код Modbus/UART/настроек/пересчёта и отдельный
набор для реальных функций Flash в Unicorn. RTOS, Flash и регистры периферии
моделируются. Проверяются 20 000 случайных/искажённых кадров, границы,
ошибки конфигурации, отложенное применение, TX-буфер, DMA TC → USART TC,
полярность DE/RE, текущая калибровка, SW1, старение данных, гистерезис,
условия обслуживания watchdog и освобождение DE при аварии. Для Flash
проверены миграция, сохранение калибровки, ошибки каждого полуслова,
повреждение CRC и 17 перезапусков CPU после стирания/программирования.
Эмулятор не моделирует электрические сигналы, реальный планировщик и точность
аппаратных таймингов. На GitHub добавлен workflow сборки и тестов.

Конфигурации EIDE и CubeIDE включают App/FreeRTOS; файлы проекта:
`4-20-to-Modbus.ioc`, `4-20-to-Modbus.code-workspace`, `.project`, `.cproject`.
Старые сгенерированные файлы Debug удалены из дерева и исключены через
.gitignore; новые сборки хранятся в build.
Исторический разбор и статус исправлений: [CODE_REVIEW.md](CODE_REVIEW.md).
План проверки устройства: [HARDWARE_TEST.md](HARDWARE_TEST.md).

## Приёмочные инструменты Windows

Чтение диагностики, проверка некорректных запросов и короткий прогон без
изменения настроек (после загрузки версии 1.1.0):

```powershell
python tools/acceptance.py --port COM6 --duration-seconds 60
```

Явно разрешённая проверка смены настроек перебирает адреса 1/126/247,
восемь скоростей, три варианта parity и 1/2 стоповых бита, затем восстанавливает
исходные активные параметры. Это 144 случая с записью Flash; запускать
только на стенде, с SW1 выключенным и доступом к нему для восстановления:

```powershell
python tools/acceptance.py --port COM6 --exercise-settings --duration-seconds 60
```

Суточный прогон запускается вручную в открытом терминале, без планировщика:

```powershell
python tools/acceptance.py --port COM6 --duration-seconds 86400 --output build/soak-24h.json
```

Прогон не требует новых калибровочных точек. Сохраняет число ответов,
ошибки, статусы, возраст данных, диагностические счётчики, диапазон
показаний и конечное состояние. Сброс устройства во время опроса считается
ошибкой. Питание/осциллограммы/состояние пайки этим скриптом не проверяются.
Полный статус приёмки: `RELEASE_CHECKLIST.md`.
